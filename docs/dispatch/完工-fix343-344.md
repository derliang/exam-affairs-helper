# 完工：#343 班級人數超過教室上限的死路、#344 新增模擬考狀態被重設（v1.26.0）

分支 `fix/343-344-class-capacity-newexam`（從 origin/main `99a1f27` 切出）。A 軌，施工對話不併 main。

## #343 根因
環境檢查（`src/ui/env.ts` 的 `classLines`）**逐班**比對「班級教室座位 < 該班人數」就亮紅燈、擋建立。
但實際排座不是逐班塞：
- 學測、會考（`src/core/exam.ts` 的 `seatExam`）把**同組**學生（高中部依文理組、國中部全體）合起來排進同組的所有班級教室。所以一班 50 人、其他班有空位時，排得下（已用測試實際排過：140 人全排入）。
- 分科依各科報名人數排考場（班級教室＋預備教室）。

所以逐班擋是錯的口徑。再加上精靈第 4 步「稍後處理」不建立班級教室，教室清單又只叫人「先匯入學生名單」，三處互指成死路。

## 修法
1. **環境檢查改成和排座一致的口徑**（`env.ts`）：
   - 學測、會考：同組學生總數 > 同組班級教室座位總數才紅燈，訊息寫出「還差幾個」與怎麼修。
   - 分科：部別學生總數 > 全部教室（含預備教室）座位才紅燈。
   - 單一班級人數超過自己教室座位（例如 50 > 49）：改成**不擋的提醒**（`EnvLine.note`）。新增模擬考頁與精靈第 4 步會顯示這段提醒，說明多出的人會坐到同組其他班級教室的空位；分科則說明依報名人數排考場、不受影響。
2. **精靈第 4 步「稍後處理，下一步」也會依名冊帶出班級教室**（`ensureClassRooms`；同名教室沿用、座位配置不動）。
3. **共用設定 → 教室清單**：名冊有學生但沒有班級教室時，顯示「依名冊帶出班級教室」鈕（給已經卡在死路的舊資料用），並列出缺哪些班；帶出後提示消失。空清單文字也改成指向這顆鈕。
4. 不悄悄改既有排座結果：只有使用者按鈕或精靈下一步才新增教室；已存在的教室與座位配置不動；排座引擎（含 D99 分科引擎）完全沒碰。

**被否決的方向**：把班級教室上限放寬到 50 以上（違反 D113 的 7×7 上限與標籤格數）；只對分科放寬、學測仍逐班擋（學測本來就是同組合併排，逐班擋是錯的口徑，學測、會考一樣會被誤擋）。

## #344
- **第 2 點（離開再回來被重設）**：新增頁的狀態原本只存在元件裡，跳去共用設定時元件卸載就沒了。改成 `NewExam` 每次變動都回報草稿（`NewExamDraft`）給 App，App 用 `useRef` 保留，從共用設定「← 回到」時帶回。從列表重新按「新增模擬考」、取消或建立後就清掉。
