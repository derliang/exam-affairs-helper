## #356（高）⑥ 考前對帳在「＋標考的」科目誤判不通過

**根因（已用假資料重現，數字與 Issue 完全相同：自然「考試 270＋自習 0」）**：
`src/ui/reconcile.ts` 的 `statusOf` 判斷「沒有標示、留在原班的人」是考試還是自習時，要先查他屬哪一組（理／文）。
查表 `classTrack` 用的是**全部班級**（`settings.classes`，國中＋高中），而排座引擎與標示規則用的是**同部別**班級（`examClasses`）。
學校同時有國中部班級、班號又與高中部重疊（1～6 班）時，排在後面的國中班（沒有組別）把高中班的組別蓋成「沒有」，
「＋標考的」規則就對不上，未標的人（留班自習）全被算成考試 → 總帳不平、M-2 紅燈、擋下載。
X 標示的科目不受影響，因為 X 標示的人身上有標示，不用查組別（所以 Issue 裡 X數B、X社會是綠的）。

**設計意圖確認**：程式原本就有「＋標考的未標者＝自習」這條（D11 標少數、D5 標示即抽離；G35 稿 v2.47「名單範圍＝考試＋自習＋未參加」），
只是查組別查錯表。所以驗收員的期望（自然 141＋129、數A 178＋92，M-2 不拿應考比全員）與設計一致，不是新規則。

**修改**：
1. `classTrack` 改用 `examClasses(doc, exam)`（與排座引擎同一份），這是本 Issue 的根因修正。
2. 同一個判斷補一條：**某組這科全不考**（D11「全考或全不考的科不標」，所以沒有規則也沒有標示），留在原班的人也算自習。
   沒補的話，例如「文組全不考數B」會同樣誤判紅燈（重現測試抓到的）。限學測（會考不走這條，會考結果不變）；
   **有規則卻沒標示**（例如 X 標示漏標）不走這條，照舊算考試，真正不平仍會紅。

**證據**：

## #357（中）③「編輯座位」展開面板被橫向捲動容器截斷

**根因兩個**：
1. 面板在表格的展開列裡，表格（`.roomtable` min-width 780）比捲動容器寬，面板跟著表格寬度（832）被容器（560）截掉。
2. 展開列唯一的儲存格也是「第一格」，吃到 `.t.compact td:first-child{white-space:nowrap}`（權重高於 `.roomtable tr.editrow td{white-space:normal}`），
   面板內說明文字整行不換行，把面板撐到約 800px，「收合」鈕與最右一排座位一定超出。

**修改**（照 DESIGN「在列下展開」，不搬位置、不改外觀）：容器加 `roomscroll`（`container-type:inline-size`），
面板包一層 `.editpane`：`position:sticky; left:0; width:100cqw; white-space:normal`——面板貼在容器可視範圍左緣、寬度＝容器可視寬度，表格左右捲動時面板不動。

**證據**（開發伺服器上渲染真的 `RoomList` 與真的 `app.css`，容器寬 560，與 Issue 量到的相同：scrollWidth 832／clientWidth 560）：
- 修正前（拿掉 class 模擬）：面板寬 832，「收合」鈕右緣 751、容器右緣 604 → 截斷。
- 修正後：班級教室 7×7、預備教室 7×7 與 7×8（56 座），捲到最左與最右，面板寬都是 560、面板 scrollWidth 560；
  「收合」鈕、全部座位格、橫排／深位步進器都在容器可視範圍內（逐一量測 `getBoundingClientRect`）。
- 寬容器（1100，不溢出）：面板寬＝容器寬，與原本相同。
- 自動檢查：`src/ui/batchB.test.tsx`〈#357〉確認容器 class、CSS 規則與面板包裝存在（測試環境沒有 DOM 版面，實際版面以上述量測為證）。
- 截圖：瀏覽器窗格截圖逾時（視窗在背景），以數值量測代替。
