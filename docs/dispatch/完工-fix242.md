# 完工：#242 名單差異處理後 ⑥ 仍被擋（1.17.1）

分支 `impl/fix-242-diffs`（從 origin/main 1.17.0 起）。

## 根因
`unresolvedDiffsOf`（src/ui/exportInput.ts）回傳 `diffs.length`（差異總數），不是「未處理」數。② 的流程是：逐筆／整組選好處理方式 → 按「套用 N 筆核對結果」才寫入名單並清掉差異。選好但還沒按套用時，⑤ 的檢核（seating.ts 用 `isResolved`）已視為處理完、可排座，⑥ 卻用總數擋下，所以「② 還有 134 筆沒處理」；被擋時三種輸出都是「將下載 0 個檔案」。與 #228（⑥ 改用 examEntries）和 #227（分組批次處理）無關，是更早就有的口徑不一致，真實名單常有大批差異才浮現。
另外 ② 在「全部選好、未套用」時仍走 `diffs.length > 0` 分支，寫「還有 0 筆…共 134 筆」。

## 修法
- `unresolvedDiffsOf` 只算 `!isResolved`，與 ⑤ 同一口徑。
- ② 全部選好未套用時：資訊色 Alert「差異都選好了（共 N 筆）：按『套用』才會更新…」，附「套用 N 筆核對結果」鈕與「回頭檢查」；徽章「差異 N 筆・已選好，待套用」；未選完時徽章顯示待處理數。
