## 二、呼叫方式（給 K2～K4）

```ts
import { readXlsx } from '../import/xlsx';
import * as M from '../core/makeup';

// ② 匯入（F-7：.xls 由 readXlsx 擋下並提示另存 .xlsx，沿用 #205）
const parse = M.parseMakeupWorkbook(await readXlsx(buf));       // 自動找表頭；多工作表一起
// parse.missing 不為空 → 請使用者指定欄位，再呼叫
//   M.parseMakeupSheet(rows, opts, sheetName, { header, columns })
// parse.problems：逐筆讓使用者「補上／修改／略過」；parse.warnings：F-12 同學號姓名或班級不一致
const roster = M.resolveMakeup(parse, resolutions, opts);
//   resolutions: { rowId, action: 'fix', row } | { rowId, action: 'skip', reason: 'transferred'|'duplicate'|'not-target'|'other', note? }
//   沒問題的列也能 skip（例：非補考對象）；fix 後會重新檢查，仍有問題就留在 roster.unresolved

// ④ 統計
const entries = M.makeupEntries(roster, settings.trackSplit);   // 人次（科目鍵、卷鍵）
M.classSubjectMatrix(entries);        // 初中、高中各一張：classes、subjects、cells、classTotals、subjectTotals、total
M.notifiedSummary(roster);            // 另行通知：bySubject、total、notifiedOnly（只有另行通知科目的學生）
M.subjectCountDistribution(entries);  // 科數分布

// ⑤ 考程（使用者可改 plan，再重算）
const plan = M.suggestPlan(entries, settings);
const schedule = M.buildSchedule(entries, settings, plan);
M.peakLoad(schedule, settings);       // F-15：各考日最擁擠時刻的同時在考人數 vs 座位

// ⑦ 產出模型（K4 依此排版；K4 若自己組最終模型，檢核要傳 K4 的模型）
const outputs = M.buildOutputs(schedule, entries, settings);

// ⑥ 檢核與閘門
const currentVersion = M.makeupVersion(roster, settings, plan);
const checks = M.runMakeupChecks({ roster, settings, plan, outputs, readback, produced, currentVersion });
const gate = M.downloadGate(checks, confirmedIds);   // gate.allowed、gate.blockers（紅）、gate.needConfirm（琥珀未確認）、gate.reasons（中文）
```

### 主要型別（`types.ts`）

- `MakeupRow`：一人一科一列。`rowId`（單表＝列號字串；多表＝「表名!列號」）、`studentId`、`name`、`oldClass`、`oldSeat`、`newClass`、`newSeat`、`subjectCode`、`subjectName`、`credit`、`attr`、`term`、`score`。
- `MakeupRoster`：`rawCount`、`included`（排程）、`notified`（另行通知）、`skipped`（含原因）、`unresolved`、`gradeOfClass`。
- `MakeupSettings`：`days`、`groups`、`rooms`、`early`（U-2）、`trackSplit?`、`independentMin?`。
  - `MakeupGroup`：同考日同一套時間的年級，`{ id, dayId, label, grades, start（分鐘）, periodMin, breakMin, roomIds? }`。`defaultMakeupGroups(grades, dayId)` 產生「高中 50 分、初中 45 分、休息 10 分、8:00」兩組。
  - `MakeupRoom`：`{ id, name, rows, depth, seatCount, disabled?, rowDepths?, use: 'class'|'mixed'|'special' }`，座位排列沿用 `classroomSeats`。
- `MakeupPlan`：每群組 `{ groupId, slots: string[][], combined: string[], early: string[] }`，可加 `pins`（指定某班某時段的教室）。
  - 時段 0..N-1：前 N-1 是獨立節；**最後一個時段是綜合節**（最後獨立科＋`combined` 全部科目，R-11）。沒有獨立節時綜合自成一節。計畫沒列到的科目自動放進綜合節（不漏人）。
- `MakeupSchedule`：`slots`（`SlotInfo`：kind＝independent／final／early、start、end）、`sittings`（一位學生一個時段一間考場一個座位，多科生一次帶多科）、`early`（總作答分鐘、`leaveAt`）、`unplaced`、`splits`。
- `CheckResult`：`{ id, title, status: 'green'|'amber'|'red'|'pending', expected, actual, diff, summary, details[] }`，details 帶 `studentId／subject／oldClass／roomId／slotId` 可跳轉。

## 三、規則怎麼落實

| 規則 | 做法 |
|---|---|
| 班級以舊班舊號（D122） | 只看 `oldClass／oldSeat`；年級由舊班判斷（`gradeOfClass`：三位數 1xx～3xx＝高一～高三、7xx～9xx＝初一～初三；或「高一溫」「初二」等文字），判斷不出列為「舊班舊號對不上」；可由 `opts.gradeOf` 換規則 |
| 問題列（F-10） | `no-id`（沒學號）、`no-name`、`bad-class`（舊班無法判斷年級、舊號無法辨識、同一舊班舊號屬於兩個學號）、`dup`（同學號同科名）、`unknown-subject`（空白，或有給 `knownSubjects` 時不在清單） |
| 同班同科同室（R-9） | 一個時段內同班的學生是一個單位，整班放進同一間 |
| 整班搬混班（R-10、D116） | 依班級順序放進第一間放得下的一般教室；放不下整班搬混班教室；再不行用特別教室；整班大於任何一間剩餘座位才拆班（記 `splits`，C-13 琥珀） |
| 時間重疊 | 同考日同一間教室在重疊時間只給一個時段（高中 08:00–08:50 與初中 08:00–08:45 不會共用同一間） |
| 座位（D119） | 每考場依班級、座號排序，照 `classroomSeats` 順序給「排-深位」 |
| 提前開考（D117） | 特別教室優先，群組開始時間開考；`leaveAt`＝他每一科在**同考日**一般時段最後一場結束時間的最大值（同科名跨年級也算，保守）；沒有人在一般時段考他的科目時＝開始＋他的總作答分鐘 |
| 離場標註（D124） | 點名單 `note`、公告列 `note`、考程表 `timetableNotes` 都是「HH:MM 前不得離場」；點名單**沒有**「最早離場」欄 |

## 五、檢核 C-1～C-15（獨立重算）

`runMakeupChecks` **不讀 `MakeupSchedule`**：應有一側取名單與設定，實有一側從產出模型（點名單、公告、備卷、座位表、考程表註記）重新點人。每項包 try/catch，算不出來＝紅。

| 項 | 應有 | 實有 | 紅／琥珀 |
|---|---|---|---|
| C-1 | 匯入列數 | 納入＋另行通知＋略過 | 不等或有未處理問題列＝紅；略過原因列在明細 |
| C-2 | 不重複學號 | 點名單上的學號＋全為另行通知 | 差異或有名單外學號＝紅 |
| C-3 | 納入人次 | 點名單上「學號＋科目」出現次數 | 漏、重複、多＝紅 |
| C-4 | 納入人次 | 各卷：統計＝點名單表尾＝點名單列＝備卷 | 任一卷不等＝紅 |
| C-5 | 0 | 超額人數＋教室時間重疊 | ＞0＝紅 |
| C-6 | 點名單人次（學生時段數） | 座位表有座位的人數 | 沒座位、重複、不在教室、兩邊名單不同＝紅 |
| C-7 | 0 | 衝突數 | 獨立節同一人兩科、同一人時間重疊＝紅 |
| C-8 | 納入人次 | 公告列數 | 每班列數不等、時間地點與點名單不同、缺班＝紅 |
| C-9 | 納入人次 | 點名單人次 | 差異或名單外學號＝紅 |
| C-10 | 納入人次 | 備卷份數 | 各卷份數、各考場份數、多科生卷數≠科數＝紅 |
| C-11 | 提前開考人數 | 已正確印出人數 | 有提前開考＝琥珀（須確認）；離場時間重算不符或沒印在點名單註欄／考程表／公告＝**紅**（見七） |
| C-12 | 提前開考人數 | 未超上限人數 | 超過 `capMin`＝琥珀 |
| C-13 | 0 | 被拆班的班數（提前開考不算，D123） | ＞0＝琥珀 |
| C-14 | 回讀檔數 | 一致檔數 | 沒傳 `readback`＝待執行；總數、各卷、版本碼不符＝紅 |
| C-15 | 已產出檔數 | 版本＝目前的檔數 | 有過期＝琥珀 |

**閘門**：C-1～C-10、C-14 紅燈禁止下載，確認也不放行；C-11～C-13、C-15 琥珀要逐項確認；C-14「待執行」不擋（回讀在產出後才跑，K4 回讀不符要另外擋交付）；其他項目待執行或缺項＝視同不通過。

## 七、我替使用者決定的事（需調度員轉使用者確認）

1. **C-11 紅燈情況**：規格表寫 C-11 不通過為「警示」。我把「有提前開考學生」設為琥珀（須確認，與稿一致），但「離場時間重算不符、或沒印在點名單註欄／考程表／公告」設為**紅**（依開工令「算不出來視同不通過」；印錯會洩題）。改回全琥珀：`checks.ts` 的 `c11` 最後一行把 `broken ? 'red' : 'amber'` 改成 `'amber'`。
2. **提前開考離場時間的「全校最後一場」**：同考日、同科名的最後一場（跨年級也算，例如高一數學提前開考，會等到高二數學考完）。較保守；若要只看同一份卷，改 `schedule.ts` 的 `lastEnd` 鍵加上年級。
3. **獨立節門檻預設 10 人**、獨立節依人數多到少排序。稿的例子（高中數英化物獨立、國文 9 人併綜合）符合；初中稿是「數學、英文＋綜合」，本預設會把初中英文 7 人併進綜合（節數更少，R-12）。
4. **綜合節定義**：最後一個時段＝最後獨立科＋所有綜合科，該時段內學生各科自由作答（R-4 例外），所以最後獨立科與綜合科同一人不算衝突。
5. **教室時間重疊**：同考日同一間教室在重疊時間只給一個時段；高中與初中同一天、時間重疊時不共用教室（不同年級要共用混班教室時，請放在同一個群組）。
6. **新增問題列種類 `no-id`（沒有學號）**：規格列的四種之外，學號空白無法認人，另列一類。
