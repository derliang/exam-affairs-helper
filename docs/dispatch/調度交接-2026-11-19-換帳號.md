## 2. 額度與交接紀律（避免做到一半額度用完）

- 放行新包前 `get_usage`：5 小時已用 ≥70% 且該包預估做不完，就不放行；≥85% 通知進行中對話到可測點 commit＋push WIP，並更新本檔；≥95% 不再發訊息，等重置。
- 每個施工對話都要**隨時 push 分支**（WIP commit 也可），調度員在每次併入、放行、收到回報後更新本檔並 push（純文件 PR 可直接併）。
- 本機 pre-push 會跑全部測試，main 若有紅燈會擋下所有人的 push：發現紅燈先分類、立刻修（版權頁測試 #426 就是這樣）。

## 3. 標準流程（A 軌）

1. 施工對話在獨立 worktree 開 PR、不自己併 main，用 `SendMessage` 回報（分支、最後 commit、測試結果、sha256）。
2. 調度員在乾淨 worktree（`C:\Users\derli\Documents\mock-exam-helper-wt-dispatcher`，detached 到 PR head SHA）跑 `npx tsc --noEmit`、`npx vitest run`、`npm run build`；動到排座／抽離／分科引擎的 PR，另跑 sha256 比對（`docs/dispatch/sha256/run-compare.sh <有 node_modules 的 repo> <舊 ref> <新 ref>`；跑前先讀過腳本；`zzsnap.test.ts.txt` 是範本）；預期只有該 PR 刻意改變的項目不同。
3. 併入 → 看 `gh run list --workflow "Deploy Pages"` 成功 → 讀回 `https://derliang.github.io/mock-exam-helper/version.json`（約 1 分鐘上線；CDN 偶有 10 分鐘快取）。
4. 每次升版必須同步改 `package.json`、`package-lock.json`、`public/version.json`（`src/versionJson.test.ts` 檢查）；決定編號接續（目前最新 D142，下一個 D143）；引擎包版號從 1.26.12 起。
5. UI 與匯出樣式一律由設計員定案；施工對話不得自行決定樣式（CLAUDE.md〈UI 一律用設計系統與共用元件〉）。
