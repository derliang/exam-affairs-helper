# 使用者驗收標準（驗收員必讀）

> 來源：使用者 2026-11-18 的原話與兩次糾正。驗收員每一輪開工前先讀本檔；與驗收員自己的做法衝突時，以本檔為準。公開 repo：不得放真實學生資料。

## 使用者原話（2026-11-18，驗收標準 1～5）
1. 用外部瀏覽器操作**線上最新版**的程式。
2. 用使用者提供的**真實資料**來操作；真實資料包含：學生名單、學生考試名單、**人工手排的座位表與標籤**。
3. 用**人工手排的資料配置好教室**（先照歷史資料的座位表，把每一班的座位配置好，使教室的總座位數與總學生數一致）。
4. 驗收**程式排的與人工排的比較，哪個比較好**。匯出檔案要**同時匯出 Word 與 PDF**，匯出在使用者提供的資料夾裡，**測試結果用 .md 儲存**。
5. 驗收時有發現問題，**一律發 GitHub Issue**。

## 糾正紀錄（為什麼要寫這些）
- **匯出檔要實際開啟看**（2026-11-18）：上一輪驗收員只比對 Word 檔內的考生編號與人數，沒有開啟；使用者開 `標籤（B4）.docx` 立刻看到每間教室第 7 排標籤被擠到下一頁、多出近空白頁（Issue #372）。**Word 與 PDF 都要實際開啟（或轉成圖片）目視檢查版面，沒目視的項目不得寫成 ✓。**
- **教室必須先照歷史座位表配置**（2026-11-18）：上一輪驗收員直接用預設教室（6 間 × 42 座＝252 座，學生 237 人），排出 42×5＋27，最後一間只有 27 人，並當成產品問題（DF-15、Issue #373）。使用者說：驗收員沒有照歷史資料的座位表，先把每一班的座位配置好，教室總座位數與總學生數一致，所以國中會考**根本不會有各班教室考生人數懸殊的問題**。不照標準配置而得到的結果不是產品缺陷，不得當 Bug 回報。
- 使用者的結論：「驗收員沒有按照標準就是亂驗」。

## 驗收員的做法（由以上推出）
1. 先讀本檔與雲端資料夾 `C:\Users\derli\我的雲端硬碟\0AI\模擬考小幫手` 內的真實資料，找出每次考試的人工手排座位表與標籤（`學測與會考`、`分科測驗`、`考試時間表`、`補考` 等；先 ls 看實況）。
2. 用外部 Chrome 操作**正式站最新版**；放行時由調度員給版號與 SHA，開工先核對版號。
3. 每一場考試：匯入學生名單與考試名單 → 依人工手排座位表設定教室（間數、每間座位數、預備教室）使總座位數＝總學生數 → 排座 → 匯出 Word 與 PDF 到雲端資料夾 → **開啟檔案目視** → 與人工手排結果逐項比較（各教室人數、班級／座號落點、標籤內容與版面），分類差異：程式與人工一致／程式較佳／人工較佳／無法判定。
4. 報告用 .md 存在雲端資料夾的驗收子資料夾（含真實姓名的內容、截圖、匯出檔只放雲端，不進公開 repo）；repo 內只放不含真實資料的摘要，以 PR 交付。
5. 發現問題一律開 GitHub Issue（標籤 `bug`、`review`），附版號、重現步驟、期望、實際；人數統計可寫，不得寫姓名與學號。
6. 不確定是產品問題還是自己設定／操作問題時，先確認設定是否符合本標準，不確定就回報調度員，不要當成 Bug。
