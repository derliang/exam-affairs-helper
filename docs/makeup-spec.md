# 補考功能規格（功能、流程、需求）

> **狀態（2026-11-17）：需求已與使用者討論定案大方向，尚未出設計稿、尚未施工。** 順序依 D33：討論定案 → 設計員出稿（假資料）→ 使用者審稿 → 才施工。
> 來源：使用者 2026-11-17 的需求說明與多輪討論，加上 105～107 學年歷史資料歸納（見 [makeup-sample-analysis.md](makeup-sample-analysis.md)）。決定見 [decisions.md](decisions.md) D113～D122，使用者原話見 [requirements.md](requirements.md)〈七、補考擴充〉，待辦見 [todo.md](todo.md) H 區。
> 公開 repo：任何地方（含設計稿、測試）不得出現真實學生姓名、學號、教師姓名；稿與測試一律用假資料。

## 一、目標與原則

1. 把例行、容易出錯的**補考行政工作**自動化：匯入不及格名單 → 統計各科人數 → 排考程與教室 → 公告與點名 → 備卷。
2. **絕對不可以遺漏任何一位需要補考的學生**。這是整個功能的第一原則，高於「排得漂亮」。因此所有安排都要**檢核與驗算、逐項對帳**，並以**統計儀表板**呈現所有數據與驗算結果。對不上就擋下輸出並說明（承 D25、requirements〈整體〉的「100% 正確」）。
3. **座位一定要精準**：每位學生每一場考試都有座位，座位數絕不少於當時人數。補考現場雖為自由入座，系統仍排座位表與參考標籤，用來檢核每個人都被安排。
4. 沿用既有 App 的操作方式與設計系統；資料只存本機（D16、D1）。

## 二、名詞

| 名詞 | 意義 |
|---|---|
| 補考場次 | 一次補考的全部設定與結果，例如「115 學年第一學期補考」。可含多個**考日**（不同年級可不同日，D115）。存放方式延續「一場一個資料夾」（D2） |
| 補考名單 | 教務系統匯出的不及格名單，一人一科一列 |
| 人次 | 一位學生的一個科目算一人次。「應補考人次」＝納入排程的名單列數 |
| 獨立節 | 一個時段中，某科目（或少數科目）獨立考的一節，通常是人數多的科目 |
| 綜合節 | 一個考日最後的一節，所有剩下的小科目併在一起，「考完為止」 |
| 多科生 | 該考日有兩科（含）以上補考的學生；**備卷時各科考卷整理成一份交給他，他自由安排作答** |
| 提前開考 | 科目太多的多科生，不等綜合節，改在特別教室第一節就開考，避免考到下午（D117） |
| 混班教室 | 收容放不下整班的零星人數，同節可有不同年級、不同科目（D116） |
| 另行通知科目 | 科屬性為 1 的科目（文化基本教材、生命教育、生涯規劃等）：只統計，不排考程（D114） |
| 考場 | 某考日某時段的一間教室 |

## 三、流程總覽

補考場次的工作區是一條固定流程，步驟可跳著點、前面有問題就標示（承 D47）；**第 ⑥ 步「檢核與對帳」同時是常駐的儀表板**，不只是最後一步。

| 步驟 | 名稱 | 做什麼 |
|---|---|---|
| ① | 補考設定 | 學期、考日（可多日、各年級對應考日）、各年級每節時長與休息、是否產生座位表／標籤 |
| ② | 匯入名單 | 匯入教務系統原始匯出檔；欄位對應；問題列逐筆處理；匯入對帳 |
| ③ | 教室設定 | 本次可用教室、座位數、混班教室、特別教室（提前開考用） |
| ④ | 人數統計 | 班級 × 科目矩陣、各科總計、另行通知清單、選組拆分 |
| ⑤ | 考程編排 | 系統建議節次與教室，使用者可調；洩題風險與離場時間 |
| ⑥ | 檢核與對帳 | 所有對帳項目與統計儀表板；全綠才可下載 |
| ⑦ | 下載 | 七項產出（Word／PDF），沿用 G15 的兩顆按鈕做法 |

## 四、功能需求

### ① 補考設定

- F-1 輸入學期；學年度依建立日期推算（承 D51）。
- F-2 **考日可設多個**。每個年級指定其考日（高三、初三下學期可提早，另有年級單獨一天的情況，見 sample-analysis〈三〉）。
- F-3 每個考日設定開始時間；高中節長預設 50 分、初中 45 分，節間休息預設 10 分（106-1 初二為 15 分），皆可改。
- F-4 設定「提前開考」的判斷上限（預設：該生各科考試時間加總超過某個結束時間就建議提前，預設值待定，D117）。
- F-5 勾選是否產生**座位表**與**座位標籤**（參考用，預設見未決 U-5）。
- F-6 新增補考場次時，自動帶入上一次補考的教室設定與時長（承 D34），所有值可手動修改。

### ② 匯入名單

- F-7 直接匯入教務系統原始匯出檔（D114）。支援 `.xlsx`；`.xls` 比照 #205 的處理（請使用者另存 .xlsx）。**含中文的檔案一律以 UTF-8／正確編碼讀取，不可亂碼**。
- F-8 欄位自動對應（學號、舊班、舊號、新班、新號、姓名、科代碼、科目、學分、科屬性、學期、分數）；對應不到的欄位請使用者指定，並預覽前幾列。**班級以舊班、舊號為準**（D122）。
- F-9 **匯入對帳**：原始列數必須等於「納入」＋「另行通知（科屬性 1）」＋「問題列（處理後歸零）」。對帳結果直接顯示在匯入結果上。
- F-10 **問題列逐筆處理**（與 G10 同一做法）：缺姓名、舊班舊號對不上、同學號同科重複、科目不認識等，每筆讓使用者選「手動補上」「修改內容」「略過」；**略過要留紀錄並出現在對帳表**，不可默默丟掉；**略過時必須從清單選原因（已轉學／重複列／非補考對象／其他），原因出現在對帳表（D123）**。全部處理完才能進下一步。
- F-11 重複匯入同一份時，要能偵測並讓使用者選「取代」或「合併」，並顯示會新增／更新／移除幾列。
- F-12 名單中同一學生可有多列（多科）；系統以「學號」認人，姓名與班級不一致時警示。

### ③ 教室設定

- F-13 **每次由使用者輸入**可用教室：名稱、橫排、深位、空位、座位數（沿用既有教室設定與座位小幫手的行列設定方式，承 D56）；系統記在本機，下次自動帶出。
- F-14 教室可標為「特別教室（提前開考）」，其餘都是一般教室；**混班教室由系統自動挑（D180，取代原「使用者標記混班教室」）**。
- F-15 教室設定頁頂部要有狀態檢核：**各時段「同時在考人數」與可用座位的比較，以最擁擠的時段為準**（不足即紅燈，承 D56）；座位每時段重複使用，不拿全日人次硬比（D123 修訂，原寫「可用座位總數與應補考人次比較」）。
- F-16 教室座位上限與標籤格配置遵循 G14 的結論（標籤一律最多 7×7，格子配置依教室座位）。

### ④ 人數統計

- F-17 產出「班級 × 科目」矩陣與各科、各班總計；初中、高中分開呈現；**選組科目拆開**（文組物理、理組化學等）。
- F-18 顯示「另行通知科目」清單與人數（不排考程，但必須列出，供對帳）。
- F-19 顯示每位多科生的科數，列出科數分布（1 科 N 人、2 科 N 人…），這是決定提前開考的依據。

### ⑤ 考程編排

- F-20 **系統建議**：依各科人數、考場容量與時間上限，建議（a）哪些科目獨立成節、哪些併入綜合節；（b）每節各科的教室分配；（c）哪些多科生提前開考與其教室（D115、D117）。**節數不固定、不綁年級**。
- F-21 使用者可調整：把某科升為獨立節或降為綜合、換教室、移動某班、指定提前開考學生。**每次調整即時重算全部檢核**，並在儀表板顯示變化。
- F-22 排法要符合第五章的硬規則；軟規則（同班同科同室、少拆班）用於建議，使用者仍可覆寫但須提示。
- F-23 一次顯示所有考日、所有年級的總覽（時間 × 教室的表格），每格顯示科目、人數、座位數與使用率。
- F-24 洩題風險與離場時間：提前開考的學生，顯示「最早可離場時間」（＝其所有科目在全校最後一場結束時間，D117）；綜合節學生一律到該時段結束才離場。

### ⑥ 檢核與對帳（常駐儀表板）

詳見第六章。

### ⑦ 下載

- F-25 七項產出見第七章；下載前必須通過「檢核與對帳」，否則擋下並說明哪一項沒過。
- F-26 每份下載檔帶**版本碼與總人次**，並由程式**回讀自己的輸出**，與定稿排程交叉驗算（承 D45）。
- F-27 名單或設定變動後，已產出的檔標示「過期」，需重新檢核與下載（承 D22）。

## 五、排程規則

### 硬規則（違反即不得輸出）

- R-1 **每筆「學生＋科目」恰好被安排一次**：有且只有一個（考日、時段、考場）。不可漏、不可重複。
- R-2 **一個科目只在一個時段考**：該科所有考場同時開考。例外：提前開考的多科生（其風險由 R-7 管制）。
- R-3 **座位足夠且精準**：每個考場每個時段的人數 ≤ 該教室座位數；每位有考試的學生在該時段都有唯一座位，無重複、無缺。
- R-4 **同一學生同一時段不可有兩個獨立科**。綜合節與提前開考的學生例外，因為他們的各科是自由作答，不是分時段。
- R-5 多科生在綜合節或提前開考，其各科考卷併為一份交給他；點名單要列出他的全部科目與卷數。
- R-6 科屬性為 1 的科目不排入任何考場、不佔座位；但必須出現在統計與對帳表。
- R-7 **離場規則（洩題管制）**：學生最早可離場時間 ＝ 他所有科目在全校最後一場結束的時間。綜合節學生到該時段結束才離場。每位提前開考的學生都要顯示並印在點名單。
- R-8 提前開考學生的總作答時間不得超過使用者設定的上限。

### 軟規則（用於建議，可覆寫）

- R-9 **同班同科盡量同一間教室**，避免跑錯教室。
- R-10 放不下整班時，**整班搬去混班教室，不拆班**（D116）。
- R-11 綜合節學生與最後一個獨立科的學生同一時段、同一教室（單科生與多科生可同室，D118）。
- R-12 同科盡量集中在少數教室；教室使用率盡量高、節數盡量少，但不得為此違反硬規則。

## 六、檢核與對帳（使用者新增的核心要求，D120）

### 6.1 原則

- 檢核項目分三色：**通過（綠）**、**警示（琥珀，須使用者逐項確認後才可往下）**、**不通過（紅，擋下輸出）**。
- 所有項目要寫出「應有／實有／差異」三個數字，差異不為 0 即不通過；不可只顯示綠燈。
- 任何變動（匯入、教室、手動調整）都會**自動重算全部項目**，儀表板即時更新。
- 每個紅燈／警示都能點開看**明細**（哪位學生、哪一科），並可跳到該處修正。
- 對帳結果隨補考場次存檔，下載檔附對帳摘要，留下查核軌跡。

### 6.2 檢核項目

| 編號 | 檢核 | 應有 ＝ 實有 | 不通過時 |
|---|---|---|---|
| C-1 | 匯入對帳 | 匯入列數 ＝ 納入＋另行通知＋略過（略過有紀錄） | 紅 |
| C-2 | 學生對帳 | 名單不重複學號數 ＝ 已安排學生數＋全為另行通知的學生數 | 紅，列出未被安排的學生 |
| C-3 | 人次對帳 | 納入人次 ＝ 已排程人次（R-1），逐筆有唯一考場 | 紅，列出漏掉或重複的學生科目 |
| C-4 | 科目人數對帳 | 各科：統計人數 ＝ 各考場該科人數加總 ＝ 點名單該科列數 ＝ 備卷份數 | 紅 |
| C-5 | 教室容量 | 每考場每時段 人數 ≤ 座位數 | 紅，標出超額教室與超額人數 |
| C-6 | 座位對帳 | 有考試的學生時段數 ＝ 已排座位數；座位無重複、無空缺 | 紅 |
| C-7 | 時間衝突 | 同一學生同一時段只有一個獨立科（R-4） | 紅 |
| C-8 | 班級公告對帳 | 每班公告列數 ＝ 該班納入人次；全校公告列數加總 ＝ 納入人次 | 紅，列出對不上的班 |
| C-9 | 點名單對帳 | 全部點名單人次加總 ＝ 納入人次；點名單上每個學號都在名單裡 | 紅 |
| C-10 | 備卷對帳 | 備卷清單各科各教室份數加總 ＝ 該科人數；多科生的卷數 ＝ 他的科數 | 紅 |
| C-11 | 洩題風險（R-7） | 每位提前開考或需延後離場的學生，離場時間已計算，且已印在點名單「註」欄、考程表與公告注意事項 | 警示，使用者確認 |
| C-12 | 提前開考上限（R-8） | 總作答時間 ≤ 上限 | 警示 |
| C-13 | 同班同科同室（R-9） | 被拆到不同教室的班級數（**提前開考的學生不算被拆班**，D123） | 警示（僅提示） |
| C-14 | 產出回讀 | 每份下載檔回讀後的總數與排程一致（F-26） | 紅 |
| C-15 | 過期檢查 | 名單或設定變動後，所有已產出檔都標過期 | 警示 |

**下載閘門**：C-1～C-10、C-14 任一為紅燈，禁止下載；C-11～C-13、C-15 須使用者確認才可往下。

### 6.3 儀表板（要隨時可看）

儀表板常駐於補考場次工作區（位置與樣式交設計員，需桌機為主、手機可讀）。內容：

1. **總覽數字**：學生數、應補考人次、另行通知人次、科目數、考日數、節數、考場數、座位總數與使用數。
2. **對帳表**：C-1～C-15 每項一列，顯示應有／實有／差異／狀態，可展開明細。
3. **考日 × 時段 × 教室矩陣**：每格顯示科目、人數、座位數與使用率。
4. **班級 × 科目人數矩陣**（含各班總計、各科總計）。
5. **備卷表**：各年級各科的人數，以及這些卷在哪個時段、分散在哪些教室、各幾份。
6. **風險與警示清單**：提前開考學生、離場時間、被拆班清單。
7. **遺漏清單**：預期永遠為空；若不為空必須是醒目的紅色。
8. **版本資訊**：產出版本碼、檢核時間、是否過期。

## 八、資料（概念）

不在此定欄位型別，施工時另訂；但下列內容必須保存，才能對帳與回溯。

- **補考名單列**：學號、舊班、舊號、新班、新號、姓名、科代碼、科目名稱、學分、科屬性、學期、分數、匯入來源檔與列號。
- **排程**：（學生，科目）→（考日，時段，考場，座位）；提前開考標記；離場時間。

## 十、給施工：切分與驗收

建議模組（邏輯層與畫面層分離，承 D18；純函式用自動測試把關）：

1. **匯入與正規化**：解析教務匯出檔、欄位對應、問題列偵測、匯入對帳（C-1）。
2. **統計**：班級 × 科目矩陣、選組拆分、多科生分布。
3. **排程引擎**：獨立節與綜合節建議、教室分配、提前開考、離場時間。演算法細節由施工對話提案，並**用 105～107 的歷史資料回測**（結果不必與人工排法相同，但必須全通過 C-1～C-10）。
4. **檢核引擎**：C-1～C-15 全部為獨立的純函式，輸入定稿排程與名單，輸出「應有／實有／差異／明細」。
5. **輸出**：O-1～O-7 與回讀驗算（C-14）。
6. **畫面**：依通過審稿的設計稿實作。

驗收要求：
- 假資料自動測試涵蓋：多考日、混班教室、提前開考、多科生、科屬性 1、重複與問題列、容量不足、洩題風險。
- **「遺漏為零」要有專門的測試**：故意從排程拿掉一筆、重複一筆、超額一間教室、改掉一份公告，檢核都必須變紅。
- 使用者另用真實資料在本機複驗（文件只記差異類型與人數，承 D99 第 5 點）。
- 版號依專案規則升次版號。
