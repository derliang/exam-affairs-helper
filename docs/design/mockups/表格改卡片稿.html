v2.75
一句話：全站所有表格不再有 min-width:560px 也不再有橫向捲軸；依內容分三種畫法——窄表（≤4 欄且每格短）原表縮進去、卡片（5 欄以上或有長文字／按鈕）容器 ≤640px 變堆疊卡片、矩陣（教室×時段、班級×項目）變「一列一張卡、裡面小標籤」。座位表依 D154（橫排≤8）一律縮放進寬度；範例標示等紙面縮圖等比縮放；長清單拿掉 max-height 內捲。
根因（讀 src/styles/app.css 推得，未實測）：table.t{min-width:560px} 撐出容器 → 才需要 .scroll；#378 的 768 溢出 40px 推論是 560px 表格＋卡片內距＋側欄後容器不到 600px；#378 ④ 的「標示方式」按鈕下橫向軸是 .seg{overflow-x:auto}，不是表格。施工後請在 375／768／1024 三個寬度量 scrollWidth ≤ clientWidth。

1　通則（取代 §10.41 第 10 列的籠統寫法）

#規則
R1畫面內不出現橫向捲軸（使用者 #378 原話：「頁面中不要有捲動軸，這樣無法閱讀」）。不得再用 .scroll、overflow-x:auto 解寬度問題；table.t 拿掉 min-width:560px。
R2三種畫法依內容選：窄表（≤4 欄、每格一行內放得下）＝保持表格；卡片（≥5 欄，或有長文字、按鈕、控制項）＝容器 ≤640px 變卡片；矩陣＝變「一列一張卡」。
R3用容器寬度判斷，不用視窗寬度：包一層 .rtw{container-type:inline-size}，用 @container (max-width:640px)。原因：同一張表放在有側欄的版面、卡片內或視窗裡，視窗寬不等於可用寬；768 視窗的卡片內寬約 696，仍是表格，手機卡片內寬約 303。不支援容器查詢的瀏覽器退回 @media (max-width:640px)。
R4卡片長相沿用 rc-pcard（ReconcilePanel 窄寬度卡片）：1px 線框、--r-md 圓角、內距 10×12；第一欄當卡片標題（粗體、16px）；其餘欄「欄名（灰 13px）左、值右」；操作鈕放卡片底部靠右；bad 列＝--danger-soft 底；缺號列＝虛線框。實作用同一份 <table> 加 td[data-label] 以 CSS 改版，不另做一份重複的卡片 DOM（rc-table／rc-cards 兩份 DOM 的作法不再擴大，既有的維持）。
R5卡片順序與表格列相同、欄名不省略；螢幕閱讀器仍讀得到表頭（thead 用視覺隱藏，不用 display:none）。
R6視窗（Modal）、紙面預覽內也適用；Modal 本身高度不夠時的「直向」捲動保留（螢幕太矮的必要退路），但視窗內不得再有橫向軸。
